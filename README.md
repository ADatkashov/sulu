# SULU — Beauty Super App

SULU («сұлу» — «красивая») — маркетплейс красоты: клиенты находят салоны и мастеров, видят реальное свободное время, записываются и платят;
бизнес управляет услугами, сотрудниками, календарём; администратор модерирует платформу. Старт — Казахстан (kk/ru/en), архитектура готова к Турции.

Три части в одном веб-приложении (`web/`) поверх одного API (`backend/`):

| Часть | URL | Кто |
|---|---|---|
| **SULU Customer** (mobile-first) | `/` | клиент |
| **SULU Business** | `/business` | владелец бизнеса |
| Кабинет мастера | `/pro` | мастер (по приглашению) |
| **SULU Admin** | `/admin` | администратор платформы |

## Реальное состояние (честно)

**Работает и проверено** (автотесты + браузерный сценарий): регистрация/вход/refresh/сброс пароля, каталог, поиск и фильтры, профили салонов/мастеров/услуг,
доступность (часы, перерывы, выходные, закрытия, буфер, lead time, лимит вперёд, часовой пояс бизнеса), запись «любой мастер», защита от двойной записи
(DB-констрейнт + advisory-lock + идемпотентность), перенос/отмена по политике, история статусов, отзывы только после завершённого визита, избранное,
уведомления in-app, промокоды (однократные), кабинет бизнеса (услуги, персонал, часы, выходные, портфолио, календарь день/неделя, клиенты, аналитика, отзывы, акции, настройки),
админка (пользователи, верификация бизнесов, категории, модерация отзывов, записи/платежи, комиссия, планы, аудит), kk/ru/en.

**Симуляции / не подключено** (ничего не выдаётся за реальное):
- Платежи: есть абстракция `PaymentProvider`, webhook с HMAC и идемпотентностью, возвраты. Реального провайдера нет — только `SIMULATED` (включается `SULU_PAYMENTS_SIMULATED=true`, везде помечен DEV/СИМУЛЯЦИЯ, в выручку не входит).
- Email / SMS / push: интерфейс `ExternalChannel` есть, провайдеров нет → доставляются только in-app уведомления. Сброс пароля и приглашения мастеров в dev-режиме логируют токен (в UI приглашения показан токен), в prod письма **не** отправляются.
- Подтверждение email/телефона, соц-вход: не реализованы (нужны внешние провайдеры).
- Карта: используется ссылка на OpenStreetMap; встроенной карты нет. Сортировка «ближайшие» работает по браузерной геопозиции (по желанию).
- Подписки/биллинг: план только записывается, цены не заданы, ничего не списывается. Комиссия фиксируется в брони, выплаты не реализованы.
- Фото: демо-данные без фото (градиентные плейсхолдеры). Загрузка портфолио/аватаров работает (локальное хранилище; для prod — S3/R2 через `StorageService`). Для продакшена нужны лицензированные фото.
- Нативные Android/iOS: Flutter-клиент лежит в `mobile/` (общий API; `flutter analyze` и `flutter test` проходят, веб-сценарий проверен). Сборки под реальные устройства/магазины не проверялись; параллельно есть PWA в `web/`.
- Локализация: клиентская часть полностью на kk/ru/en; кабинеты бизнеса/админа — ru/en, недостающие kk-строки падают на ru. Турецкий: схема БД и колонки готовы, словарь не добавлен.
- Не сделано: earliest-availability как фильтр/сортировка в списках (есть «ближайшее время» на карточках услуг/мастеров), полноценная серверная валидация загрузок изображений через перекодирование, rate limit общий для кластера (сейчас in-memory), dependency-vulnerability scan.

## Запуск локально

Требуется: Java 21, Maven, Node 22, PostgreSQL 16 (или `docker compose up db`).

```bash
# 1. БД (пример)
createuser -s sulu && createdb -O sulu sulu && createdb -O sulu sulu_test   # пароль sulu (только dev)

# 2. Backend (профиль dev: демо-данные, симуляция платежей, dev-секреты, admin@sulu.local / Admin12345!)
cd backend && SPRING_PROFILES_ACTIVE=dev mvn spring-boot:run      # http://localhost:8080 · OpenAPI: /swagger-ui.html

# 3. Web
cd web && npm install && npm run dev                              # http://localhost:5173
```

Демо-логины (только dev, пароль `Demo12345!`): `anna@demo.sulu` (клиент), `owner@demo.sulu` (владелец), `master@demo.sulu` (мастер); админ `admin@sulu.local` / `Admin12345!`.
Демо-бизнесы вымышлены и помечены «ДЕМО». Промокод `WELCOME10`.

Без профиля dev backend не стартует, пока не задан `SULU_JWT_SECRET` (см. `.env.example`). Миграции Flyway применяются автоматически; схема не создаётся Hibernate'ом.

## Архитектура

Модульный монолит (`backend/src/main/java/com/sulu/`): `identity`, `security`, `catalog`, `booking` (доступность + запись), `payment`, `engagement` (отзывы, избранное, уведомления, аудит),
`business` (кабинет, персонал), `admin`, `storage`, `seed`. JdbcClient + SQL (без ORM-сущностей наружу), DTO-проекции в camelCase, единый формат ошибок `{code,message,details}`.
Деньги — целые минорные единицы + валюта. Время — `timestamptz`, отображение в часовом поясе бизнеса.

Ключевые гарантии:
- **Нет двойных записей**: `EXCLUDE USING gist (professional_id, during) WHERE status IN ('PENDING','CONFIRMED')` + `pg_advisory_xact_lock` + повторная проверка слота в транзакции (тест на 10 параллельных запросов).
- **Авторизация на сервере**: роль и статус пользователя читаются из БД на каждый запрос; `/api/biz/{id}` проверяет владение (чужой бизнес = 404); админ-маршруты закрыты `ROLE_PLATFORM_ADMIN`; саморегистрация только CUSTOMER/BUSINESS_OWNER.
- **Статусы брони** — конечный автомат (`PENDING→CONFIRMED|REJECTED|CANCELLED`, `CONFIRMED→COMPLETED|NO_SHOW|CANCELLED`), клиент статус напрямую не ставит.
- **Платежи**: клиентский «успех» ничего не значит; статус меняют только события провайдера/вебхука (HMAC, `UNIQUE(provider,event_id)`).
- **Приватность**: публичные отзывы показывают «Имя Ф.», экспорт данных `GET /api/me/export`, удаление аккаунта обезличивает данные.

Подробнее: `docs/ARCHITECTURE.md`, `docs/PRODUCTION.md`.

## Что нужно для продакшена (внешнее)
Платёжный провайдер (карты/Apple Pay/Google Pay/Kaspi и т.д.) и его webhook-секрет; email/SMS/push провайдеры; S3-совместимое хранилище; секреты `SULU_JWT_SECRET`, БД; домен/TLS; лицензированные фото; юридическая оценка соответствия (GDPR/закон РК о персональных данных) — не проводилась.
